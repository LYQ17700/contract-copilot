### **给前端工程师**

前端只需要依赖原有的高亮契约，不需要适配新字段：

- 条款高亮继续使用 `clauses[].start/end`。
- 风险定位继续使用 `findings[].start/end`。
- 单位仍是 `preprocessed.text` 的字符下标。
- `preprocessed.flow` 与 `preprocessed.map` 仍为服务端内部索引，不下发。
- `document.text` 与条款 `body` 仍保持严格一致。

新增的 `clauses[].items` 是向后兼容的附加字段，可用于后续“条下款/项”高亮，但当前前端可以忽略：

```
{
  "id": "C1",
  "heading": "第一条 租金",
  "body": "第一条 租金\n月租金2000元。\n（一）押金为一个月租金",
  "start": 0,
  "end": 38,
  "items": [
    {
      "id": "C1.1",
      "marker": "（一）押金为一个月租金",
      "text": "（一）押金为一个月租金",
      "start": 19,
      "end": 34
    }
  ]
}
```

前端需要注意：`items` 可能为空数组，不能假设每个条款都有款项。

图片上传现在支持 `bmp/tif/tiff/webp`，但 Tesseract 实际识别还依赖 `chi_sim.traineddata`；前端展示 `/health` 时应继续以 `ocr.probe.ready` 为准。

### **给 Backend A**

需要同步两处边界变化：

- 上传白名单新增 `bmp/tif/tiff/webp`，Backend A 不需要改 `PARSERS` 注册表，因为 `tiff/tif/bmp/webp` 早已映射到 `parseImage`。
- `parseImage` 返回的 `pageCount` 现在可能大于 1，多页 TIFF 会按真实页数进入 `ParsedDocument`。

另外，OCR Provider 现在具备真正的超时和重试，Backend A 不需要 catch 特定错误类型；超时错误会以普通异常向上抛，`NotImplementedError` 仍保持 501 语义。

### **给 Pod2 工程师**

Pod2 接触到的 `PreprocessedDocument` 结构没有破坏性变化：

- `documentId`、`text`、`clauses`、`flow`、`map`、`stats` 字段保持不变。
- `clauses[].body` 仍然是 `text.slice(start, end)` 的完整原文。
- 新增的 `clauses[].items[]` 是附加信息，Pod2 可以选择忽略，也可以用来做更细粒度的定位。
- `clause.items[].start/end` 同样是 `text` 的字符下标。

Pod2 需要知道的一点是：条款切分现在支持 `一、`、`附件一`、`Article 3`、`Clause 3`、`Section 3`、`1.` 等编号，因此同一份合同可能比旧版本切出更多或不同粒度的条款。风险规则如果按“命中条款数”做统计，需要重新跑一次基线。

视觉模型 OCR 不再只返回纯文本，`VISION_LLM_STRUCTURED=1` 时可返回 `transcript + clauses` 线索，但这部分只作为 Provider 输出，最终仍然由后端 B 的 `splitClauses()` 统一切分。

**OCR Provider 接口**

Provider 契约保持不变：

```
{
  name,
  ready(): Promise<{ ready, reason?, code?, ... }>,
  recognize(buffer, ctx): Promise<{
    text,
    confidence?,
    pageCount?,
    rotateRadians?,
    clauses?,
    notices?
  }>,
  shutdown?(): Promise<void>
}
```

Tesseract 的行为变化：

- worker 首次识别时冷启动，之后复用。
- 并发请求通过串行队列执行，不会同时调用同一个 worker。
- 识别超时后 worker 会被销毁，下次请求重新冷启动。
- 默认使用 PSM 6 和 `rotateAuto`。
- 多页 TIFF 会逐页识别，最后用空行拼接。

视觉模型的行为变化：

- 请求前把图片统一归一化为 PNG。
- 单页 PNG 超过 `VISION_MAX_BYTES` 会立即失败并提示压缩或降低分辨率。
- 网络错误、429、5xx 会重试；401/403/413 不重试。
- 支持 OpenAI Chat Completions 风格与 Responses 风格返回结构的文本提取。
- 模型返回 Markdown JSON 代码块、直接 JSON、纯文本都能解析。

### **环境变量交接**

Tesseract：

```
OCR_TESSERACT_WORKER_TIMEOUT_MS=60000
OCR_TESSERACT_TIMEOUT_MS=60000
OCR_TESSERACT_RETRIES=2
OCR_TESSERACT_AUTO_ROTATE=1
OCR_TESSERACT_PSM=6
OCR_TESSERACT_DPI=
```

视觉模型：

```
VISION_LLM_KEY=
VISION_LLM_BASE_URL=https://api.openai.com/v1
VISION_LLM_MODEL=gpt-5-vision
VISION_LLM_TIMEOUT_MS=90000
VISION_LLM_RETRIES=2
VISION_MAX_BYTES=8388608
VISION_LLM_STRUCTURED=0
```

Tesseract 运行还依赖：

- `tesseract.js` 可用。
- `chi_sim.traineddata` 存在，路径由 `TESSDATA_PREFIX` 或 `backend/var/tessdata/` 指定。
- `sharp` 可用于图像归一化与多页 TIFF。本机 Codex 运行时已提供，正式部署执行 `npm i sharp`。
